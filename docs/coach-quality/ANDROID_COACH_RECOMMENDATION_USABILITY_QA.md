# Coach Swole Cat: Android recommendation UX acceptance checklist

**Stage:** Unpublished PR #88 usability preview, not an app update-channel or Beta release.
**Build:** `.github/workflows/android-usability-preview.yml` uploads an artifact only. It never calls `gh release`, never edits `updates/testing.json` and never pushes main. The app version is changed **only inside the CI runner** from 0.93.4/code 139 to `0.93.5-preview.1`/code 140. Package ID stays `com.jlingenfelter.swolecat.testing`, using the exact permanent Testing signing certificate. The installed Beta package is separate.

**Important:** The signed preview is an in-place *Testing app update*, not a side-by-side installation. Device QA requires the owner's voluntary install after the artifact and signing digest verify. Before installation, confirm important Testing-local workouts have a separate recoverable backup, and do not sign out of or switch cloud accounts for this test. If the device has Testing already at code >=140, do not attempt to overwrite/downgrade. The next real Testing update following a preview install must use **code 141 or greater** (unless the installed version has a still-higher code). Never uninstall to force a preview update. No existing cloud or account cleanup is part of this QA.

## Phase A: CI and mobile screen-width contract

- [ ] Full regular validation workflow passes at latest PR head, including Phase 1-3 frozen program tests and preview acceptance/decline/save parity.
- [ ] Simulated Android WebView interaction gate passes at 320 / 360 / 390 / 430 / 480 CSS-pixel widths. This verifies markup, key button text, opt-in state, safe scroll container, wrapping/touch-target stylesheet rules, and non-mutation of persisted data; **jsdom does not measure actual pixels or replace Android device testing**.
- [ ] Unpublished APK builds with package ID `com.jlingenfelter.swolecat.testing`, code 140, versionName `0.93.5-preview.1`.
- [ ] APK is verified using Android `apksigner` with the expected permanent Testing certificate SHA-256 `d53f277c5b92311d78e9eb3bdb692ad489734797f2430827400213f38b7cee53`. Artifact also includes APK SHA-256.
- [ ] No GitHub release or Testing/Beta update manifest was modified.

## Phase B: On-device manual review (owner)

1. On a backed-up **Testing** device, install the unpublished signed APK **only if** the owner chooses to run this test. Android should show an update to Swole Cat Testing; do not uninstall the installed app. Verify app opens and existing routines remain intact.
2. Open Coach. Ask for a **3-day full-body gym program, ~45 minutes, muscle building**. Answer the setup questions as usual. Review the preview without touching recommendations: the original program should remain present and Save still works.
3. Tap **Review suggestions**. Confirm text is readable without ellipses at normal and enlarged display/text sizes; all three action buttons are fully tappable, with no side scrolling or controls hidden under the keyboard, bottom navigation or composer.
4. On **Full Body B**, confirm Coach explains **Overhead Press → Lat Pulldown**, around **41 → 41 minutes**, clearly as an **optional** suggestion. Tap **Keep Original**, verify it keeps Overhead Press, and verify the declined suggestion does not immediately pop up again. No program should save yet.
5. Generate the same request again, tap **Review suggestions**, then **Use Recommendation** on Full Body B. Verify it now has **Lat Pulldown**, not Overhead Press; no new sixth exercise; shoulder presses remain on Full Body A/C. Reopen preview/refine a minor detail and confirm the accepted change remains.
6. The separate optional suggestion on Full Body A is **2 sets of Seated Leg Curl**. Accept only if testing that path; check preview shows 2 sets and around 48 minutes rather than 44. Confirm a normal decline leaves the previous exercise list unchanged.
7. Tap **Try Another Swap** on a fresh suggestion, and verify the existing manual swap behavior is offered rather than accepting Coach's suggestion automatically. The user must remain able to make another exercise choice.
8. Test scrolling the preview down to the Save action, with the Coach prompt and Android keyboard both open and closed. Confirm no unreachable buttons, accidental taps, clipped text, sticky-layer overlap or app crashes.
9. Only on a throwaway synthetic program you intend to retain in Testing, tap **Save Program**. Open Routines and verify saved exercises and working sets exactly match the preview. Confirm existing workout logs and history were not changed.
10. Share a short screen recording or screenshots plus any concerns about button size, scroll, confusing language, which action feels primary, or whether the recommendation would actually be useful. **Do not test Beta**.

**QA exit:** Sign-off needs the owner's real Android usability observation as well as green CI. A real device UI screenshot/recording is not generated by jsdom CI; do not mark device QA passed based solely on markup tests. No release, merge, publish or migration proceeds without separate approval.
